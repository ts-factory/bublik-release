Release v2.20.0

November 10, 2026 · 22 min read
Kostromin Danil
Bublik UI Maintainer
Rybchenko Natalia
Bublik Backend Maintainer

We're excited to announce Bublik v2.20.0!
This release adds an iteration matrix, lets you classify results across several runs from History and the Multiple runs page, and introduces access tokens for agents and scripts. The Runs charts are redesigned, the sidebar gets a project switcher, and filters take values and expressions in one field.

What's New​

Iteration Matrix
Lay a test's iterations out by their parameters and spot failing combinations at a glance.

Classify From History and Multiple Runs
Pick results from several runs and classify them under one issue in one go.

Access Tokens
Let an MCP client, a CI job or a script call Bublik as you.

Redesigned Runs Charts
Group by day, week or month, and click a bar to list its runs.

Project Switcher
A searchable project list at the top of the sidebar that remembers your pick.

Values and Expressions in One Field
Filter runs and history by values and expressions in the same field.

Highlights​

Iteration Matrix​

Open a test's iterations on the run page and click Matrix to see them as a grid of parameters, so failure patterns stand out.

  1. List / Matrix. Filters apply to both views, and the layout is kept in the URL.
  2. Suggested layouts: Balanced, Densest, Expose gaps and Nested rows.
  3. Parameters. Put each one on Rows, Cols, Facet or leave it out. Two parameters on one axis are nested.
  4. Cell colours by Result or by Coverage.
  5. Facets. Filter shows one facet value at a time, Split draws a matrix per value. Margins adds totals.
  6. Cells show P, F or S, an iteration count, or unexpected out of total, such as 2/4. Hatched cells never ran, dashed ones are filtered out.

Click a cell to open its iterations:

  1. The cell's parameter values.
  2. Click an iteration to pick it. Picks from several cells and from the list join one selection.
  3. Select All picks every failed or classified iteration of the cell.
  4. Classify opens the classify form.

Classify From History and Multiple Runs​

Classification is no longer limited to the run page. One selection can now hold results of several runs, picked on the Multiple runs page, in History or in the iteration matrix. Only failed or already classified results of one project can be picked.

  1. Each result names its run.
  2. Click rows to pick them, or use Select All.
  3. Selected Results lists the picks with their runs.
  4. Classify opens the form for all of them.
  5. The selection pill shows how many results and runs are picked.

When the results come from several runs, Match scope in the form shows the rules it will write:

  1. A card per test path.
  2. A rule per group of runs with the same important tags.
  3. Narrow each rule on its own. Remove values to match more widely.

The selection is classified all at once: every result, or none.

In History, click a row in List Of Results, or a whole group in Groups Of Results:

  1. Click a group to pick all of its results.
  2. Selected Results lists the picks.
  3. Select All picks every result on the page.
  4. Classify files them under one issue.
  5. The selection pill shows the count.

Picks survive filter, page and view changes. Classified rows show the SUPPRESSED or STALE chip, as on the run page.

Access Tokens​

A personal access token lets an AI agent through the MCP server, a CI job or a script call Bublik with your permissions. Open Settings → Access Tokens from the account menu.

  1. New token.
  2. Name it after where it's used, such as nightly-ci.
  3. Expires in 7, 30 or 90 days, or Never.

  1. Copy token. It's shown only once.
  2. MCP client setup gives ready-to-copy MCP config and curl snippets.
  3. Active tokens with their last use and expiry. Revoke takes effect on the next request.

Admins can see and revoke every user's tokens under Admin → Access Tokens:

  1. Owner.
  2. Status: Active, Expired or Revoked.
  3. Revoke.

Good to know:

  • MCP clients without a token still work anonymously. A bad, expired or revoked token gets a 401.
  • Tokens can't manage tokens or users.
  • Up to 20 active tokens, and 10 new ones per hour.
  • Deactivating a user revokes their tokens for good.
  • On a headless server: python manage.py issue_user_token <email> --name <name> --expires 30 (7, 30, 90 or never).

Redesigned Runs Charts​

Runs → Charts now shows runs and test results over time.

  1. Group by Day, Week or Month.
  2. Overview: runs by conclusion, tests, pass rate and NOK results.
  3. Click a bar to list its runs in a drawer.

The two charts zoom and hover together.

Project Switcher​

The project picker is now a searchable list at the top of the sidebar.

  1. Find project, or press P anywhere.
  2. Each project's last run and run count.
  3. New Project and Manage for admins.

New tabs open with the last project you picked. Links with a project open as before.

Values and Expressions in One Field​

Runs metas and the History filters (tags, labels, branches, revisions, parameters) no longer split values and expressions into two fields.

  1. Value / Expression. Typing &, |, !, ( or ) switches to an expression.
  2. A value chip, such as mix: warn.
  3. An expression chip, such as sfc | ice. Click a chip to edit it.

Old links open with the same filters.

Import Tasks​

  • Revoke unfinished imports in Admin → Import. They get the REVOKED status and Try Again. A run revoked mid-import may miss post-processing such as categorization.
  • Copy Log copies time, level and module, not just messages.
  • XML log imports now match rgt-bublik-json: correct dates in every timezone, no more cut or split values with line breaks, & or colons, and logs without an execution plan import again.
  • Line graphs with sequence numbers on the X axis are saved. Force import older runs to get them.
  • Force import keeps the compromised mark, and a failed one no longer drops the run's logs link.
  • A lost database connection is retried after 1, 2 and 4 minutes. An import interrupted three times fails instead of running forever.
  • Live import keeps the keys, notes and tag expressions of results, and accepts null values.
  • The import log no longer shows raw internal errors when a failure email can't be sent.
  • On bare metal, the Celery worker restarts after a failure.

Links From Run Metadata​

Labels holding URLs, such as a pull request, can now show as short links (#94, a 7-character hash) in the run's Info block and on the dashboard. Assign the label to a category in the project's meta config:

"Docker PR": {
  "type": "label",
  "set-patterns": ["^DOCKER_PR$"]
}

Then add the category to SPECIAL_CATEGORIES in per_conf, or add a go_url column to DASHBOARD_COLUMNS:

{
  "key": "Docker PR",
  "label": "Docker PR",
  "payload": "go_url"
}

Existing runs pick it up when the config is saved.

Open Tabs Move to the New Version​

Tabs left open during an update no longer end up at "Something went wrong". They check for a new version every five minutes and load it on the next page you open. Bare-metal installs need the new nginx config, see Backend Update.

Help Opens the User Guide​

The ? buttons open the matching section of the new User Guide in these docs, replacing the old help dialogs.

Smaller Improvements​

  • Page layout. On screens wider than 1920px, choose Full width, Left sidebar or Centered in Settings → Appearance → Layout.

  • Log layouts. Settings → Preferences sets the layout log links open in:

    1. Default log layout: Tree + info + log.
    2. Log layout from Runs: Tree + log.
    3. Log layout from History: Info + log.

    The defaults match the old behaviour.

  • Run and issue pages. Issues, Log, Reports, Results and Rules links moved from the page headers to the sidebar.

  • Run table. Totals sit next to the columns they sum, and counts are right-aligned.

  • Rules. Edit and Duplicate show the saved values, Duplicate keeps the disposition, and a new Match only failures without any verdict option.

  • MCP. New search_docs, get_doc and list_docs tools, and an in-memory response cache per server.

  • Fixes. Old /log/<run>/<id> links keep their layout, /chat says when chat is off, History no longer serves another query's cache, and docs pages with a dot in their name no longer 404.

Admin Section​

Backend Update​

warning

The nginx_conf and run_side_servers deployment steps require root rights. If you don't have root access, you must manually update the Nginx configuration using bublik/templates/nginx.bublik.template and reload Nginx.

  1. cd bublik
  2. git remote update
  3. git checkout v2.20.0
  4. ./scripts/deploy --steps django_settings celery_service nginx_conf migrate_db run_side_servers run_services

Frontend Update​

  1. Trigger the workflow in your frontend repository
  2. Synchronize the mirrors
  3. cd bublik-ui
  4. git remote update
  5. git checkout v2.20.0

Documentation Update​

  1. Trigger the workflow in your frontend repository
  2. Synchronize the mirrors
  3. cd bublik-docs
  4. git remote update
  5. git checkout v2.20.0

Docker Instance Update​

# 1. Backup the current db
task backup:create

# 2. Update the image tag in the .env file
sed -i "s/^IMAGE_TAG=.*/IMAGE_TAG=2.20.0/" .env

# 3. Pull the latest docker image
task pull

# 4. Start the docker container
task up
